# Как добавить новую статью

## 1. Создать файл

Новый `.md` файл в нужной папке:

- `articles/ru/` — русские статьи
- `articles/en/` — английские статьи

Имя файла становится частью адреса, поэтому только латиница, цифры и дефис:
`articles/ru/nastroika-routera.md` → `https://protectorrtd.github.io/articles/ru/nastroika-routera.html`

## 2. Заполнить front matter

Это блок между двумя `---` в самом верху файла:

```yaml
---
title: "Название статьи"
date: 2026-09-03
description: "Короткое описание — оно попадёт в превью на главной"
---
```

Обязателен только `title` — **без него статья не появится в списке на главной**.
Это удобно: убрали `title`, и статья временно скрыта из индекса.

`date` управляет сортировкой (новые сверху). `layout`, `author` и `lang`
подставляются автоматически из `defaults` в `_config.yml` — писать их не нужно.

## 3. Написать текст

Обычный Markdown. Что поддерживается:

- `**жирный**`, `*курсив*`, `` `код` ``, `[ссылки](https://example.com)`
- Заголовки `##`, `###` — из них автоматически строится оглавление слева
- Блоки кода с подсветкой (Rouge):

  ~~~
  ```js
  console.log('привет');
  ```
  ~~~

- Таблицы в стиле GitHub
- Выноски GitHub:

  ```
  > [!NOTE]
  > [!TIP]
  > [!IMPORTANT]
  > [!WARNING]
  > [!CAUTION]
  ```

- Картинки: положить в `assets/img/` и вставить как `![подпись](/assets/img/file.png)`

## 4. Опубликовать

```bash
git add .
git commit -m "новая статья: название"
git push
```

GitHub Pages пересоберёт сайт сам, обычно за 1–2 минуты.

## Черновики

Незаконченное держите в `drafts/` — эта папка в `exclude`, на сайт не попадает.
Когда статья готова — просто переносите файл в `articles/ru/` или `articles/en/`.

Если не хотите, чтобы черновики вообще уходили на GitHub, раскомментируйте
строку `drafts/` в `.gitignore`.
